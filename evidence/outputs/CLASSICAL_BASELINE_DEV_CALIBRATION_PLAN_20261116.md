# 经典基线 DEV 校准与冻结计划

日期：2026-11-16。该计划先固定参数候选集与选择规则，再运行 DEV 校准。独立 TEST/确认数据不参与参数选择，也不由本脚本读取。

状态补记（2026-11-16）：本计划所列 9 个 Max-TF 和 8 个 GMM-OMP 候选 DEV pilot 均已运行且均未通过冻结门槛，未进入全 DEV 复核或独立确认。GMM-OMP 的相位原点疑点已由解析关系与合成回归测试排除为本轮性能问题的可行修复方向；因此本补记不授权扩大搜索或重新运行。未来若提出新候选/算法版本，必须另建版本化计划并先复核来源公式和 DEV 数据身份。

## 比较对象和输入边界

- Max-TF、GMM-OMP 只接收观测波形和发射 LFM 的公开参数。
- BCS 使用真实非干扰采样支撑，属于 oracle 参考；它单独报告，不作为同信息条件的竞争基线。
- 训练与 DEV parent 通过 receipt 中固定 seed/count 对应的 parent ID 区间核查不重叠。参数校准使用 `data/paper2_1103/dev.npz`，其 SHA 与 receipt 必须吻合。
- 校准阶段仅用 64 个等距 DEV parent 搜索候选；胜出配置再在全部 256 个 DEV parent 上复核。候选逐 parent 原始波形不回传，也不纳入仓库。

## 预先固定的候选范围

Max-TF 固定 `hop_length=12`、`n_fft=128`、`min_clean_frames=2`、`smoothing_bins=3`，搜索 `window_length ∈ {35, 51, 67}` 与 `peak_quantile ∈ {0.60, 0.70, 0.80}`，共 9 组。

GMM-OMP 固定两分量 GMM、最多 100 次 EM 更新和其余数值稳定参数，搜索 OMP 稀疏度 `K ∈ {4, 8, 12, 16}` 与相对残差容差 `{10⁻³, 10⁻²}`，共 8 组。

BCS 在 8 个等距 DEV parent、3 种干扰类型和指定脉冲位置构成的 DEV 样本上，以 6 个正则系数 `{10⁻⁴, 3×10⁻⁴, 10⁻³, 3×10⁻³, 10⁻², 3×10⁻²}` 运行影响矩阵 GCV；记录场景数、每个候选的 GCV 分数及收敛率。BCS 的 oracle 支撑边界不因 GCV 而改变。

## 冻结规则

候选必须在 DEV 上通过以下约束：输出全为有限值、没有全零 parent、目标损伤 `damage ≤ 1`、受扰背景帧虚警 `frame_pfa_jammer ≤ 0.10`。可行者按 DEV 平均 SJRIF 从高到低选择；并列时依次按 Pd 更高、damage 更低、`u_nmse` 更低排序。Max-TF 与 GMM-OMP 的胜出参数随后在全部 DEV parent 上复核；任一算法未通过完整 DEV 约束，则标记门控失败，不进入独立确认。

该阈值是本轮预设的校准门槛，不是来源论文的标准，也不代表最终部署虚警指标。候选范围、阈值与打分顺序在分析前固定，确认结果不得用于改变它们。

## 运行与留存

正式计算只在服务器 B 的 `D:/code/Xin/ISRJ_222` 运行，物理 GPU 1；TEST 或确认数据仅在配置冻结且门控通过后另行生成/读取。每个候选完成即写独立 JSON 收据，包含数据 SHA、parent ID 摘要、源码 SHA、配置与指标，支持中断后安全续跑。最终 freeze 记录仅含轻量摘要，不含训练数据、模型权重或逐样本数组。

校准门控通过后，再用冻结配置对独立数据做一次确认，并同已冻结的新模型、Max-TF、GMM-OMP 比较；BCS 结果仍标为 oracle。若门控失败，先记录失败原因和 DEV 诊断，再修订校准计划并留存新版本，不能查看确认结果后改参数。
