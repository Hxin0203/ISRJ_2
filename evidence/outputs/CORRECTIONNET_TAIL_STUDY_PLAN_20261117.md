# CorrectionNet 本模型尾部损失验证方案

方案日期：2026-11-17。本文是新实验的冻结协议；队列部署与实际保存轮数另见进展快照。本方案不声称新模型已有性能提升。

## 为什么调整优先级

此前安排 U-Net 作为损失和表征的筛查骨干，目的是把结构变化和训练目标的作用分开。但如果筛查长期只在 U-Net 上进行，就无法回答第二篇论文的 CorrectionNet 是否真正得到改善。原模型已有八个 seed 的 256 轮模型和结构／损失消融；它们保留不动。本阶段把原模型的新损失验证提前到 GPU 1 的下一项，不要求 U-Net 尾部损失先取得正结果。

## 两个训练组

两组均使用原始 `paper2.network.CorrectionNet`，保留去斜、RMS 归一化和原骨干。注册参数 112756，其中实际参与当前前向图的参数为 59714，未参与部分为 53042。不将未使用分支解释为本模型的有效创新。

| 组别 | 新训练任务 | 训练目标 | 用途 |
| --- | --- | --- | --- |
| 本模型原损失控制 | `correction_original_control_20261117_v1` | endpoint + 0.1 PC + damage | 同环境重新训练的控制组 |
| 本模型新增尾部损失 | `correction_mf_tail_20261117_v1` | endpoint + 0.1 PC + damage + 0.05 tail | 只改变尾部项权重 |

每组 seed 为 17、29、41，各训练 256 轮，固定在第 256 轮进行配对 DEV 评价。使用同一 512-parent 训练集、每轮 1536 个 parent-family records、48 次更新、batch 32、microbatch 8。每 seed 总更新数 12288。Adam、学习率计划、梯度裁剪阈值 5、FP32、关闭 TF32、确定性设置在两组间一致。同 seed 初始模型张量逐一检查相等；不从 U-Net 或历史旧模型权重继续训练。

重新训练原损失控制是为了控制微批及精度等运行条件。历史 Full 模型只作描述性运行差异参照，不替代这一控制组。新实验不能直接称为八 seed 验证；八 seed 的旧模型与本次三 seed 新优化必须区分。

## 损失的数学含义与限制

设校正量为 C(y)，恢复量为 y − C(y)。原损失继续约束四状态重建、脉压误差及加入目标前后的校正差异。新增项直接复用已冻结的 `tools/unet_tail_loss/objective.py`，不为本模型另调权重或阈值。

尾部项在目标缺席的含干扰状态上计算 j − C(j + e)，经 600 点 LFM 匹配滤波、物理时延 0..1200 及 8 脉冲 FFT 得到距离–多普勒残差功率；用已知训练噪声 e 的平均 RD 功率归一化。在检测有效距离格 36:1165 中取最大的 8 个 RD 单元，惩罚超过理想化 436 参考单元、Pfa = 1e-6 的 CA-CFAR 功率倍率所对应 dB 阈值的平滑超额量，平滑温度为 3 dB。原损失控制组也记录同一 tail 诊断，但其训练权重为 0。

这是关注残余相干峰的训练代理，并不等于真实 CFAR 判决，也不保证恒虚警。训练已知噪声只用于监督损失，推理不读取分解真值。评价继续使用统一的实际雷达处理与 CFAR 流程。

## 评价与决策

在同一 DEV parent 上配对，三类干扰先在 parent 内平均，报告全部三个 seed。包括整体误差、endpoint／PC／damage 训练曲线、目标增量损伤、干扰残差、SJRIF、Pd、含干扰目标缺席帧虚警和其他统一评价器指标。不得以含新增项的 total loss 绝对值跨组排序，须看分量及雷达指标。

尾部组相对新原损失控制的筛查规则：三个 seed 的含干扰帧虚警变化中位数小于 0；每个 seed 的 Pd 变化至少为 −0.02；三个 seed 的目标损伤变化均值不超过 +0.005。该规则用于分配后续资源，不是统计显著性或已证明非劣性的结论。控制组相对历史 Full 不应用这个择优门槛。

原 U-Net／新增 tail U-Net／原损失 CorrectionNet／新增 tail CorrectionNet 构成骨干×损失的四格。四格描述和损失效应差可检查收益是否依赖骨干，但三 seed 与同一 DEV 的结果仍不能充当独立确认。固定训练预算，不挑最佳 seed 或轮数。正结果在新确认集复核，负结果同样保存。长程、频率或归一化在 U-Net 上的收益，随后需要转移到本模型逐项验证，不能直接写成本模型的贡献。

## 服务器调度与故障恢复

仅在服务器 B `rsdr-b`、`D:/code/Xin/ISRJ_222`、物理 GPU 1 执行，两组串行。GPU UUID 固定为 `GPU-bb60dd3a-738e-2398-908f-7f77ac05549b`。本机不运行训练或数值优化预检。

GPU 1 顺序：当前 U-Net tail 三 seed 训练及 DEV → 本模型新原损失控制三 seed 及 DEV → 本模型新 tail 三 seed 及配对 DEV → 释放原 U-Net dilation 队列。等待阶段不分配训练预算，不运行 GPU 优化预检。原 dilation 控制器通过其已有的 PAUSE 接口等待，不改冻结源码，不中断正在计算的任务；仅移除本实验拥有且内容匹配的 PAUSE。若新实验失败，保留 PAUSE 并记录失败，人工检查后再继续。GPU 0 的归一化及频率独立筛查按原冻结方案继续。

启动前验证 host/path/device、数据及 receipt SHA、依赖完成摘要与源码 SHA；资源准入需连续三个样本 GPU 利用率低于 20%、空闲显存至少 12 GiB、CPU 低于 85%、可用 RAM 与磁盘各至少 8 GiB。运行数值预检验证有限梯度、有效参数数、模型／优化器／随机状态精确恢复及下一步数值误差不超过 1e-6。预检失败不训练，不绕过保护，也不在本机回退。

每个完成的 epoch 保存不可变恢复点及 model／optimizer／RNG，另存每 32 轮里程碑和逐轮损失。恢复及评价前核 SHA、源码和数据身份。保留所有旧模型及失败证据。两组各沿用累计 96 小时预算，不自动无限重试。控制器重启可从最后验证通过的轮次恢复；服务器重启后不承诺自动重启控制器。
