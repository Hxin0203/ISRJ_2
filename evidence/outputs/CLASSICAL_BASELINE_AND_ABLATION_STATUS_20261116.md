# ISRJ_2 实验阶段进展与结果

日期：2026-11-16。本文汇总本轮经典基线校准、BCS 正则敏感性分析，以及服务器 B 上已完成的 U-Net/结构消融流水线。所有基线选参只使用 DEV；U-Net/消融的独立确认比较依据其单独冻结方案执行。这里不将不同角色、数据口径或 oracle 信息条件的结果混为一谈。

## 经典基线校准

Max-TF 的 9 个预设参数组合和 GMM-OMP 的 8 个预设组合均已在服务器 B（`D:/code/Xin/ISRJ_222`）完成 DEV pilot。输入 DEV 文件 SHA-256 为 `0e71bf9ddb43a0a89f62ce3e09e741d9ea20c19596ab75aebc787cd1e7796dc1`，覆盖 64 个等距 parent。校准门槛预先固定为有限且非全零输出、目标损伤 `damage ≤ 1`、受扰背景帧虚警 `frame_pfa_jammer ≤ 0.10`。只有 pilot 合格项才会做完整 256-parent DEV 复核；通过完整复核后才进入独立确认。

17 个候选均未达到门槛，因此没有候选进入 256-parent 复核，也没有 Max-TF/GMM-OMP 参数被冻结或用于确认集。Max-TF 最佳 SJRIF 候选（窗长 35、分位数 0.80）在 pilot 上 SJRIF 为 5.28 dB，但 `damage=25.77`、`frame_pfa_jammer=0.547`。GMM-OMP 的最佳 SJRIF 候选（K=8、残差容差 0.01）为 5.68 dB，但 `damage=8.16`、`frame_pfa_jammer=1.00`。因此本轮可以得出的结论是“所检验的候选配置未满足预设约束”，不能据此声称这两类算法整体无效。独立确认数据没有用于其选参或评估。

## BCS DEV-only 正则敏感性

BCS 使用真实干扰支撑，属于 oracle 信息条件，只作为单独的参考上界，不是同信息条件的直接竞争基线。GCV 在 24 个 DEV 场景上从预设 6 个 λ 中选择 `λ=0.001`；8 个 DEV parent 的 oracle 摘要收敛率为 1。按计划补做的 `λ=0.01` 对照使用相同的 8 个 DEV parent，冻结配置 SHA 前后相同，且没有读取确认数据。

`λ=0.001` 的 8-parent DEV 摘要为 SJRIF 15.26 dB、damage 0.305、Pd 0.708、受扰背景帧 Pfa 0，脉冲求解收敛率 1。`λ=0.01` 对应为 SJRIF 15.63 dB、damage 0.248、Pd 0.833、受扰背景帧 Pfa 0，收敛率 1。该小样本对照显示这两个 λ 在所抽取 DEV 子集上的表现接近，不能替代全 DEV 复核，也不能把 λ=0.01 事后改为默认值；原 GCV 选择仍是 `0.001`。

## U-Net 与结构/损失消融

服务器端队列已完成 15 次 256-epoch 训练（U-Net 及完整模型各 3 seeds；四项消融各 3 seeds），并完成 5 种模型变体的确认比较。训练结果和每 32 epoch 检查点按流水线留存；轻量汇总副本位于 `evidence/outputs/unet_ablation_3seed_256_20261115/`。队列完成时间为 2026-11-16 12:21 UTC。确认测试使用 2048 parents，每个方法和 seed 在独立 1024-parent 校准集上按经验 1% 帧虚警阈值定标，确认集与留出确认数据无重叠。

在三 seed、epoch-256 的独立确认中，U-Net 的 Pd 均值为 0.510，受扰帧 Pfa 均值为 0.0082，目标增量直接损伤均值为 0.0463。完整模型三 seed 对应为 Pd 0.471、Pfa 0.0086、损伤 0.0609。no-damage 消融 Pd 为 0.547、Pfa 0.0100、损伤为 0.125；它显示移除损伤项提升了检测概率，但明显损害目标回波保真。所有数值来自当前 3-seed 方案，不能替代更多随机种子的稳健性验证。该确认口径中的检测器、目标门限和损伤定义应与论文方法和结果表保持一致。

U-Net 与完整模型参数量匹配，均有 59,714 个活动参数。服务器 RTX 5060 Ti、FP32/TF32 关闭、单条波形前向的中位延迟分别约为 2.20 ms 和 3.39 ms；该测量仅覆盖网络前向，不含解调、脉压、多普勒、CFAR 和数据搬运。
